## Before committing any of this

`watch.3mf` is **141 MB and GitHub rejects a file over 100 MB** — not a warning,
a refused push. `watch.html` at 54 MB is over the 50 MB warning threshold but
goes through. The two options for the 3MF are Git LFS or a Release attachment,
and `README.md` above already recommends the second. The other three files are
small enough to commit normally.

|---|---|
| `--cell 0.1mm` | `eta_pos_16_barrel_bridge_envelope`, 68 pinched edges |
| `--cell 0.15mm` | `seconds_hand_envelope`, **0 triangles** |

So the cell-size search the README describes has run out of answers on this
revision, and the reason is structural rather than bad luck: **the model spans
0.04 mm (hairspring wire) to 32 mm (case), and no single cell holds both.** The
default — each definition meshed on its own grid — is what per-definition grids
exist for, and it is the only setting that writes a valid file here.

**16 763 598 triangles, 8 381 766 vertices, 83 objects, 103 build items**, read
back and confirmed by **lib3mf 2.5.0**, the 3MF Consortium's own reader, which
agrees with cade on every one of those numbers. 1.32 GB as cade writes it
(entries stored); the file here is that archive deflated, which is the README's
own recipe and is legal 3MF — lib3mf and `trimesh` both return identical
geometry from it.

### One file: `watch_assembly.step`

Written by **cade's own assembly writer**, not by an external composer — 43
definitions placed 54 times, with the AP214 product tree, the part names and the
colours, 2.2 MB, at `-n 256`.

The way round the whole-or-nothing rule is not to weaken it. That rule is about
a file that *silently* drops parts, and what it forbids is worth keeping. So
`../watch_exact.cade` is a generated Cade source that **states** which
definitions it contains and where each one sits — every placement is the world
frame `tools/cadeval.py` flattens out of the model — and what cade writes from
it is a *complete* export of a stated selection rather than a truncated export
of the watch. The file lists the 45 definitions left out, by name, in its own
header. Regenerate it with `tools/make_step_assembly.py`; the selection is read
from `step/`, so the two artefacts cannot disagree about what exports.

**Gate.** `cade export`'s own check re-imports the file and runs `verify`, and
it is structurally blind to the product tree, because
`NEXT_ASSEMBLY_USAGE_OCCURRENCE` appears nowhere in cade's importer — a file
whose placements were all wrong would pass it. Read back with **OpenCASCADE
7.9** (`tools/occt-assembly.py` in the cade tree): **54 occurrences, 43 of 43
solids valid, 0 invalid**, each at its located bounding box — the four train
jewels on their own pivots, the crystal at z −2.5 to −1.5, the crown at x 20,
the barrel at 99.995 mm³.

**Why `-n 256` and not the default.** An assembly export runs one `-n` for every
definition in it, and three of the 43 need a raised count of their own — the
barrel (256), the automatic lower bridge and the hour hand (192). At `-n 128`
the file writes in 45 seconds with 40 parts and those three refused; at 256 it
takes about eight minutes and takes all 43. The refusal names them either way,
so there is no silent version of this choice.

### A faceted whole-assembly STEP is now possible and is still not the answer

`cade export --part <assembly> --faceted` was **accepted and silently ignored**
until today — `export` matched the assembly branch before it looked at the flag
— and that is fixed upstream, with a test that fails against the old behaviour.
It does not rescue this model. A faceted `ADVANCED_FACE` costs **503 bytes per
triangle**, measured, so 16.8 M of them is **8.4 GB**, against 141 MB for the
same triangles as a deflated 3MF; and every coarser grid that would shrink it
breaks a part, per the table above. For a mesh of the whole watch, the 3MF is
the format.

## Interactive

- **`watch.html`** — drag to orbit, wheel to zoom, shift-drag to pan, the cube
  snaps to an axis, **hover a row to light that part, click to hide it**, and a
  slider explodes the assembly. Hide the case, caseback and crystal and the
  movement is underneath. Meshed at `-n 48`; `-n 64` and `-n 128` are the same
  command and give 95 MB and 381 MB.
- **`watch-raymarch.html`** — 1.6 MB for the same 103 placements, because the
  page raymarches cade's field per pixel rather than carrying a mesh. Needs
  WebGPU. It has **not** been confirmed rendering: the container it was built in
  loses the WebGPU device on a shader that size, which is a fact about that
  software rasteriser and not about the page, but unverified is unverified.

## Reproducing

```sh
cade build  watch.cade -o watch.3mf  --part watch
cade view   watch.cade -o watch.html --part watch -n 48
cade view   watch.cade -o watch-raymarch.html --part watch --raymarch
cade export eta_2824_design/<module>.cade -o step/<part>.step --part <part> -n 128
```
